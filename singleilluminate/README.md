# singleilluminate -- single-hole illumination, unified and joined into the system

A small, dedicated module for one factor -- pinhole brightness (percent of natural-
pupil illuminance transmitted) -- kept separate from the full wave-optics pipeline
because illumination here is closed-form (`(a_hole/D_pupil)^2`, an area ratio) and
needs no ASM propagation at all. No "recommended aperture" or "recommended pitch" is
computed anywhere in this folder: it is an exploration/comparison tool for brightness
alone, meant to sit alongside the rest of this project's blur/MTF/Strehl/acuity
comparisons, not to rank against or replace them.

## Scope: single-hole only -- read this before extending anything here

This module was originally specified to also unify a **multi-hole array** photometry
model (`stage_array/array_photometry.py`, with worst/mean/best-case discrete lattice
alignment, square/hex packing, and a no-ghost-pitch cross-check against real r_EE(P)
data) alongside the single-hole one. That `stage_array/` module **does not exist
anywhere in this project** -- confirmed by an exhaustive search (grep across every
`.py`/`.md` file for `no_ghost`, `array_fig`, `worst_case`, `relative_retinal_
illuminance_array`, hex-packing code, etc. -- nothing found). There is no prior
array-photometry or no-ghost-pitch implementation to import from.

Per this project's standing rule (see `stage3_human_vision/literature.py`'s whole
citation discipline), **physics is never invented here to fill that gap**. So:

- `illumination_model.py::percent_illumination()` raises `NotImplementedError` for
  any multi-hole call (`N_holes>1` or `pitch_um` given) -- loud and documented, not a
  silent wrong-answer fallback to the single-hole formula.
- `run_illumination_sweep.py` only ever writes `row_type="single_hole"` rows.
- `streamlit_app.py`'s Array and No-ghost-cross-check tabs are explicit "blocked"
  placeholders, not filled with invented numbers.
- `join_with_system.py` only joins single-hole illumination into the shared grid.

**If `stage_array/` is built later**, `percent_illumination()`'s multi-hole branch
is the one place to extend -- see that function's docstring.

## Files

| File | Role |
|---|---|
| `illumination_model.py` | Unified interface (`percent_illumination()`), single-hole only. Imports `stage3a/transmission.py::relative_illuminance()` directly -- the physics is not reimplemented. Runs a cross-check at import time between `stage3a`'s and `stage3_human_vision/photometry.py`'s independently-implemented single-hole formulas (both exist; the array one doesn't) and raises if they ever diverge. |
| `run_illumination_sweep.py` | Single-hole sweep: `a_hole_um` over the same 15 discrete values `stage3a/multi_EE_sweep.csv` uses (75-2000um, for direct comparability), `D_pupil_um` in [3000, 4000, 5000] (natural pupil varies by lighting/individual). Writes `outputs/illumination_results.csv`. |
| `streamlit_app.py` | Lightweight, no-wave-optics interactive explorer. Tab 1 (Single-hole) is live; Tabs 2-3 (Array, No-ghost cross-check) are explicit blocked placeholders per the scope note above. |
| `join_with_system.py` | Adds `percent_illumination` as a first-class column to `stage3_integrated`'s combined grid (via importing, not modifying, `combine_metrics.build_combined_grid()`) and renders one comparison figure in the same aperture-x-myopia heatmap layout `stage3_integrated/generate_plots.py::plot_sensitivity_heatmaps` already uses. See below. |
| `outputs/` | `illumination_results.csv` (this module's own sweep output). |

## Does NOT modify

`stage1_v2/`, `stage2/`, `stage2_fixed/`, `stage3a/`, `stage3_human_vision/`, or
`stage3_integrated/` -- all read-only libraries, imported from following the same
import-boundary pattern `stage2_fixed/pipeline_junction.py` already uses for
`stage1_v2`. `join_with_system.py` writes *new* files into
`stage3_integrated/outputs/` (`combined_grid_with_illumination.csv`,
`illumination_sensitivity_heatmap.png`) rather than overwriting
`combined_grid_550nm_12mm.csv` itself, since that file is regenerated by
`stage3_integrated/combine_metrics.py`'s own `main()` and would silently drop this
addition on its next run if written into directly.

## What `join_with_system.py` actually does

1. Calls `stage3_integrated/combine_metrics.py::build_combined_grid()` (imported, not
   copied) to get its existing 105-point (15 aperture x 7 M) grid.
2. Adds one column, `percent_illumination`, via `illumination_model.percent_
   illumination()` -- asserts the row count is unchanged (same discipline
   `build_combined_grid()` itself already uses for its own merge).
3. Cross-checks the new column against the grid's pre-existing `relative_retinal_
   illuminance` column (from `stage3_human_vision/photometry.py`) -- confirmed
   **exact agreement** (both trace to the same `(a_hole/D_pupil)^2` formula). This
   new column's value is not numerically new; what's new is that it now has explicit
   `singleilluminate` provenance and sits in a namespace a future array-aware
   `percent_illumination` extension can grow into without a name collision.
4. Renders `illumination_sensitivity_heatmap.png` in the exact aperture-x-myopia
   `imshow`/viridis/pivot_table layout `plot_sensitivity_heatmaps` already uses for
   every other metric, with the 6.25%/9% brightness-floor apertures (from
   `stage3a/README.md`'s own finding) marked. **Expected, not a bug**: every column
   of this heatmap is constant across the M axis, since illumination is a purely
   geometric area ratio, independent of myopia/defocus -- stated on the plot itself.
5. Does **not** recompute `combine_metrics.py::constrained_optimum_all_metrics()`'s
   brightness-floor-constrained optimization -- that logic already exists and
   already consumes an illumination column; this script's only job is exposing the
   raw number as a first-class, traceable column.

## Follow-up flagged, not silently done

`stage_v1_simulator/streamlit_app.py`'s Live Explorer tab currently recomputes
`stage3a`'s illumination formula separately from this module. A short note has been
added to `stage_v1_simulator/README.md` (README only -- its code is untouched)
flagging that it should eventually read from `singleilluminate/illumination_model.py`
instead, and that this app is now available as a lighter-weight, illumination-only
companion. Not done here as a silent refactor of another stage's code.

## Running it

```
cd singleilluminate
python3 illumination_model.py         # prints the cross-check result + a few example points
python3 run_illumination_sweep.py     # writes outputs/illumination_results.csv
streamlit run streamlit_app.py        # interactive explorer (standalone, works without step above too)
python3 join_with_system.py           # joins into stage3_integrated/outputs/ (writes new files there)
```

Requires `numpy`, `pandas`, `matplotlib`, `streamlit` (same as the rest of this
project).
