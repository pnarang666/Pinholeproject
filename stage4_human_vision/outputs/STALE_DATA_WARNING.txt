WHY THEY ARE STALE
-------------------
All six files predate the 2026-08-06 fix to stage4_human_vision/pipeline.py
(the stage2/ -> stage2_fixed/ import-shadowing bug -- see RESULTS.md's own
"Re-run against corrected optics" section for the full root-cause writeup).
Before that fix, pipeline.py silently imported the deprecated, physically
wrong stage2/phase2_retina.py instead of the corrected stage2_fixed/ version
-- meaning every number in the six files above was computed against the
WRONG eye optics.

HOW THIS WAS FOUND (2026-09-28)
---------------------------------
While preparing a deviation/R^2 report for the array-design project
(Array_Design/array_geometry_lab/predicted_logmar_analysis/), the same
(a_hole_um=750, M=2D) input was independently re-run with CURRENT code and
gave 0.076 logMAR -- not the 1.010 logMAR recorded in the stale
validation_predicted_vs_observed.csv. File mtimes confirmed the stale files
predate the fix by 8 days. This is the SAME category of defect as the
grid_N=2048 staleness bug already found and fixed elsewhere in this project
(new_sweeps/run_acuity_sweep.py, 2026-09-12/13) -- a real upstream fix that
was never propagated to every file that depended on the old behavior.
